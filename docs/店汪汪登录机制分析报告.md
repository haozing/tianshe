## 一、登录流程概述

店汪汪采用**WebView2 浏览器登录 + Cookie 提取 + 本地持久化存储**的架构，整个登录流程分为以下几个阶段：

### 1.1 首次登录流程 (WebView2)

```
用户操作 → form_login_webview2 弹窗 → WebView2 加载抖店登录页
    → 用户在 WebView2 中完成抖音扫码/密码登录
    → 抖店 SSO 回调 → 登录成功检测 (NavigationCompleted 事件)
    → HandleLoginSuccessAsync() 提取所有 Cookie
    → 构造 DouYinLoginedCurrentUser 对象
    → 序列化存储到 LiteDB 数据库 + INI 配置文件
```

**关键 URL 常量:**
- 登录页: `https://fxg.jinritemai.com/login/common`
- SSO 回调: `https://fxg.jinritemai.com/passport/sso/login/callback`
- 登出页: `https://fxg.jinritemai.com/`
- 首次登录选店: `https://fxg.jinritemai.com/ffa/chooseEntries`

### 1.2 登录检测机制

`form_login_webview2` 类包含以下关键字段和机制：

| 字段/方法 | 作用 |
|-----------|------|
| `cookieCheckTimer` (Timer) | 定时检查 Cookie 是否已获取到登录态 |
| `SetupLoginDetection()` | 设置登录检测逻辑 |
| `HandleLoginSuccessAsync()` | 登录成功后的异步处理，提取 `List<CoreWebView2Cookie>` |
| `WebView2_NavigationCompleted` | 页面导航完成后检查是否到达回调 URL |
| `WebView2_SourceChanged` | 源变化时检测登录状态 |
| `CoreWebView2_WebResourceRequested` | 拦截网络请求，监控登录凭据 |
| `_blankPageCheckTimer` (Timer) | 检测空白页面异常 |
| `ClearCk()` | 清除已有 Cookie（重新登录时调用） |

### 1.3 密码登录流程 (辅助方式)

通过 `DouDianApiClientHelper.LoginAsync(account, password)` 方法实现：
- 返回类型: `Task<(bool success, string data, string message)>`
- 支持账号密码自动填充 (`AutoFillLogin`)
- `btn_save_login_Click` 处理保存登录信息
- `IsValidEmailOrPhone` 验证输入格式

### 2.2 存储层架构（三重持久化）

#### (1) LiteDB 数据库存储

```csharp
// loginInfo 静态构造函数中的关键代码
ShopInfoCol = CommonUtils.db.GetCollection<DouYinLoginedCurrentUser>("店铺集合名");
```

- **数据库引擎:** LiteDB (LiteDB.Async)
- **集合名:** 通过 `ZYXDNGuarder._04.30()` 混淆（DNGuard 保护）
- **数据结构:** `DouYinLoginedCurrentUser` 作为文档存储，`ObjectId` 为主键
- **存储路径:** 应用目录下的 Data 文件夹

#### (2) INI 配置文件加密存储

```csharp
// loginInfo 静态构造函数

SeriralizeInfo seriralizeInfo = JsonSerializer.Deserialize<SeriralizeInfo>(text);
```

**SeriralizeInfo 类结构:**
- `CurrentUser`: `DouYinLoginedCurrentUser` — 当前登录用户
- `shopCks`: `Dictionary<long, DouYinLoginedCurrentUser>` — 所有店铺的 Cookie 映射表

**加密方式:** AES 加密 (`AesCryptoServiceProvider`) + Base64 编码

#### (3) WebView2 缓存（浏览器原生存储）

```

```

WebView2 使用 `Login_User` 作为用户数据目录，独立于系统浏览器。

## 三、会话保持与自动续期机制

### 3.1 多平台会话管理

店汪汪管理**三个平台**的独立会话：

| 平台 | 基础 URL | 会话认证方法 |
|------|----------|-------------|
| 抖店后台 | `fxg.jinritemai.com` | `ActivePhpSession()` + `login()` |
| 百应平台 | `buyin.jinritemai.com` | `AuthenticateBuyinSession()` |
| 罗盘平台 | `compass.jinritemai.com` | `AuthenticateCompassSession()` |

### 3.2 会话验证流程

```csharp
// DouYinLoginedCurrentUser 中的会话验证方法链
Task<bool> CheckLogin()          // 检查抖店登录状态
Task<bool> PHPSESSIDIsInvalid()  // 检查 PHPSESSID 是否有效
Task<bool> accountIsInvalid()    // 检查账号是否有效
Task<bool> autoLogin()           // 自动登录
```

**CheckLogin 返回的 CheckLoginResponse 结构:**
```csharp
public class CheckLoginResponse {
    public bool subject_has_login;    // 主体是否已登录
    public bool deputy_has_login;     // 子账号是否已登录
    public int error_code;            // 错误码
    public string description;        // 描述
    public string next;               // 下一步
    public string redirect_url;       // 重定向 URL
    public string sec_subject_uid;    // 安全主体 UID
    public string sec_user_id;        // 安全用户 ID
    public string ticket;             // SSO ticket
}
```

### 3.3 CSRF Token 自动刷新

```csharp
// 以下方法用于在请求时动态查询/刷新 CSRF Token
void query_fxg_csrf_session_id(string apiurl)   // 查询抖店 CSRF 会话
void queryfxgcsrftoken(string apiurl)            // 查询抖店 CSRF Token
void query_commpass_csrf_session_id(string apiurl) // 查询罗盘 CSRF 会话
void querycommpasscsrftoken(string apiurl)       // 查询罗盘 CSRF Token
```

**CSRF Token 过期检测:**
- `fxg_x_secsdk_csrf_token_expiredat` + `fxg_x_secsdk_csrf_token_expired` 控制抖店 Token 有效期
- `compass_x_secsdk_csrf_token_expiredat` + `compass_x_secsdk_csrf_token_expired` 控制罗盘 Token 有效期

### 3.4 API 请求参数签名机制

每次 API 请求都需要以下参数（从日志中确认）：

| 参数 | 说明 | 生成方式 |
|------|------|---------|
| `appid` | 固定值 `1` | 硬编码 |
| `_bid` | 业务上下文 | `ecom_market_shop` 或 `ffa_goods` |
| `s` | 随机数值 | 会话/签名值 |
| `_` | Unix 时间戳 (ms) | 当前时间 |
| `verifyFp` / `fp` | 设备指纹 | `VerificationFpManager.GetRandomVerifyFp()` |
| `msToken` | 反爬虫 Token | 长 Base64 字符串 (150+ 字符) |
| `a_bogus` | 反爬虫签名 | Base64 编码 (100+ 字符) |

### 3.5 会话失效检测

当日志中出现以下响应时，表示会话已失效：
```json
{"code":"10008","msg":"登录信息已失效，请重新登录~","st":10000}
```

应用会自动重试（最多 3 次），全部失败后标记 `sessionIsInvalid = true`。

## 四、过期后重新登录机制

### 4.1 自动重新登录

```csharp
// DouYinLoginedCurrentUser 中
Task<bool> autoLogin()       // 自动登录尝试
void kickout()               // 踢出/强制登出
void resetUserCk()           // 重置用户 Cookie
```

### 4.2 手动重新登录流程

当 `sessionIsInvalid = true` 时：
1. 调用 `loginOrChangeShopById(long id)` 切换/重新登录指定店铺
2. 弹出 `form_login_webview2` 窗口
3. 可能先调用 `ClearCk()` 清除旧 Cookie
4. 通过 `_needClearCookieOnInit` 控制是否在初始化时清除
5. WebView2 重新加载登录页
6. 用户重新扫码或输入密码

### 4.3 Cookie 清除机制

**CefSharp 侧:**
```csharp
// DeleteCookieVisitor 实现 CefSharp.ICookieVisitor
public class DeleteCookieVisitor : ICookieVisitor, IDisposable {
    public string Name;  // 要删除的 Cookie 名称
    public bool Visit(Cookie cookie, int count, int total, ref bool deleteCookie);
}
```

**WebView2 侧:**
- `HandleLoginSuccessAsync()` 中通过 `CoreWebView2.CookieManager.GetCookies()` 获取 `List<CoreWebView2Cookie>`
- WebView2 的 Cookie 存储在 `Login_User/EBWebView/Default/Network/Cookies` (SQLite)

### 5.2 DouYinLoginedCurrentUser 文档中的敏感字段

- 配置节名和键名通过 `ZYXDNGuarder` 混淆

## 六、CefSharp 和 WebView2 在登录中的角色

### 6.1 WebView2 — 主要登录入口

**用途:** 用户交互式登录（扫码/密码登录）

- **类:** `form_login_webview2`
- **用户数据目录:** `douShopTool.exe.WebView2/Login_User/`
- **WebView2 版本:** 149.0.4022.62（从日志中获取）
- **核心事件:**
  - `CoreWebView2InitializationCompleted` → 初始化完成
  - `NavigationCompleted` → 页面加载完成（检测登录回调）
  - `SourceChanged` → URL 变化（检测登录状态）
  - `WebResourceRequested` → 网络请求拦截（提取认证信息）
  - `NewWindowRequested` → 新窗口请求处理
- **JavaScript 桥接:** `JsToCSharpBridge` 类，通过 `CoreWebView2.AddHostObjectToScript` 暴露给网页
- **外部 URI 处理:** `CoreWebView2LaunchingExternalUriSchemeEventArgs` 事件处理

### 6.2 CefSharp — 后台操作浏览器

**用途:** 后台自动化操作（商品管理、营销活动等非登录操作）

- **类:** `CefSharpRequestHandler`、`CommonUtils.Cwb_AddressChanged` 等
- **请求处理:**
  - `CefSharpRequestHandler` 实现 `IRequestHandler` 接口
  - `OnUpdateCookie` 回调 — Cookie 更新通知
  - `UserAgent` — 自定义 UserAgent
  - `OnCertificateError` — SSL 证书错误处理
  - `GetResourceRequestHandler` — 资源请求拦截
- **Cookie 操作:** `DeleteCookieVisitor` 实现 `ICookieVisitor` 用于 Cookie 删除
- **地址变化监听:** `Cwb_AddressChanged` 事件处理，包含 `ChromiumWebBrowser` 引用

### 6.3 双浏览器协作模式

```
WebView2 (登录)                CefSharp (操作)
┌─────────────────┐           ┌─────────────────┐
│ 抖店登录页面     │           │ 抖店后台页面     │
│ 扫码/密码登录    │           │ 商品/订单管理    │
│ Cookie 提取      │  ──传递──→│ Cookie 注入      │
│ SSO 回调检测     │           │ API 调用         │
└─────────────────┘           └─────────────────┘
```

1. **WebView2** 负责用户登录，获取完整 Cookie 集合
2. 登录成功后，通过 `HandleLoginSuccessAsync()` 提取所有 `CoreWebView2Cookie`
3. Cookie 被存储到 `DouYinLoginedCurrentUser` 对象
4. 对象持久化到 LiteDB + INI 文件
5. **CefSharp** 后台浏览器使用这些 Cookie 执行自动化操作
6. 两个浏览器共享同一套认证体系，但用户数据目录独立

## 七、安全机制总结

### 7.1 代码保护
- **DNGuard HVM** 混淆保护，关键方法体被替换为 `throw new Exception("Error, DNGuard Runtime library not loaded!")`
- 字符串/常量通过 `ZYXDNGuarder` 类混淆
- 运行时需要 DNGuard Runtime Library 加载

### 7.2 数据加密
- AES 加密存储 Cookie 数据
- 28 个 64 字符十六进制密钥/秘密值
- 16+ 个 20 字符字母数字 Token
- `DouShopLoginEncryptor` 专门处理登录加密

### 7.3 风控对抗
- `VerificationHandler` — 验证码处理（滑块/短信）
- `VerificationFpManager` — 设备指纹池管理（最多 10 个指纹）
- `RiskControlSmsHelper` — 短信验证码处理
- `RandomBrowserUa` — 随机浏览器 UserAgent
- `a_bogus` / `msToken` — 抖音反爬虫签名
- 请求重试机制 (`ExecuteWithRetry` / `ExecuteWithRetryAsync`，最多 3 次)
- DoH DNS 解析回退 (`ResolveDomainViaDohAsync`)

### 7.4 外部通信
- 后端控制服务器: `system.fandikj.com` (HTTP，非 HTTPS)
- 版本检查: `system.fandikj.com/prod-api/version/getVersion`
- OEM 配置: `system.fandikj.com/prod-api/oemConfMessage/getOemConf`
- Volcengine AI: `ark.cn-beijing.volces.com` (豆包 AI)
- 卡密系统: `ChargeKami()` 方法 + `kamiExpireTime` 过期管理
