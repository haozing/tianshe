## 2. 总体架构

小尊宝工具箱 V2.1.6 是一个 Electron 壳 + 远程 Web 应用 + 远程热更新浏览器插件代码的组合。

### 2.1 分层结构

```text
小尊宝工具箱_2.1.6.exe
  └─ NSIS 安装器
      └─ app-64.7z
          └─ Electron Runtime
              └─ resources/app.asar
                  ├─ dist-electron/main/index.js
                  ├─ dist-electron/main/preload/index.js
                  ├─ dist-electron/main/work-server/*
                  └─ dist-electron/plugin/正式版30.2.2/*

运行时：
  Electron 主窗口
    └─ 加载 https://apptool.zzbtool.com
        └─ Vue/Vite 单页应用
            ├─ 抖店经营、商品、营销、资金、违规等功能页
            ├─ 通过 window.client 调用本地能力
            └─ 通过平台 Cookie/隐藏窗口/HTTP 代理访问抖店接口

浏览器插件：
  service-worker.js
    └─ 拉取 plug*.zzbtool.com 配置
        └─ 下载 v3_all.js / v3_ext.css
            └─ eval 注入到抖店、罗盘、PDD 等页面
```

### 2.2 Electron 主进程

核心文件：

- `analysis_unpack\app_asar\dist-electron\main\config.js`
- `analysis_unpack\app_asar\dist-electron\main\index.js`
- `analysis_unpack\app_asar\dist-electron\main\preload\index.js`
- `analysis_unpack\app_asar\dist-electron\main\work-server\*.js`

关键配置：

- 应用标题：`小尊宝工具箱 V2.1.6`
- 首页地址：`https://apptool.zzbtool.com`
- BrowserWindow：固定窗口，约 `904 x 649`，无边框，不可 resize。
- Session partition：`persist:myappzzbtool`
- WebPreferences：开启 `nodeIntegration`，开启 `contextIsolation`，关闭 Web 安全限制。

主进程提供的本地能力包括：

- Cookie 读写：读取、设置、删除平台 Cookie。
- HTTP 请求：以本地进程或指定 session 发起请求。
- 文件上传/下载：上传文件、保存 buffer、下载到指定目录、取消下载。
- BrowserWindow 管理：打开隐藏窗口、执行页面 JS、重载首页、关闭窗口。
- 本地 SQLite：`better-sqlite3` 封装增删改查。
- 系统能力：通知、选择目录、打开资源管理器、崩溃日志、版本信息、自动更新。

### 2.3 Preload 与 Web 应用协作

Preload 将本地能力挂载到 `window.client`。远程 Vue 页面通过这些能力完成桌面端增强：

- 用本地 Cookie/session 调平台接口。
- 用隐藏窗口完成需要浏览器上下文的接口签名、登录态校验、滑块验证页面加载。
- 用本地 DB 保存批处理任务、预览结果、失败日志。
- 用文件系统能力导入商品 ID、导出 Excel 日志。
- 用下载器拉取平台导出文件，例如罗盘/经营版导出结果。

### 2.4 浏览器插件热更新机制

本地插件目录：

- `analysis_unpack\app_asar\dist-electron\plugin\正式版30.2.2`

核心文件：

- `js\service-worker.js`
- `popup\*`
- `other\jquery / crypto-js / jszip / html2canvas / qrcode / hotkeys / jsencrypt 等`

插件启动后请求：

```text
https://plug{Date.now() % 100}.zzbtool.com/zzbPlug/v3config
```

请求头包含渠道、插件 ID、版本、作者、当前 URL 等信息。服务端返回 JS/CSS/Popup URL。插件随后：

1. 注入本地基础库。
2. 下载远程 `v3_all.js` 与 CSS。
3. 缓存代码到内存映射。
4. 使用 `chrome.scripting.executeScript` 在页面 MAIN world 中 `eval(code)` 执行。
5. 通过 service worker 代理 fetch/ajax、Cookie、上传、下载、标签页/窗口管理、动态规则请求头等。

这意味着很多页面按钮、平台页增强、跨站请求逻辑并不在安装包固定代码里，而在远程 `v3_all.js` 中热更新。

## 4. 通用业务设计

### 4.1 店铺与登录态

多数功能都以“店铺”为处理单元。页面通常先从本地或远程服务获取店铺列表，随后按店铺 session/cookie 执行平台请求。

常见店铺字段：

- 店铺名称
- 店铺 ID
- 登录状态
- 分组
- 功能包/订购状态
- session partition 或本地登录上下文

执行前会校验：

- 店铺是否在库中。
- 店铺是否登录有效。
- 是否处于回收站、无权限、订购状态异常等状态。
- 是否需要滑块验证或二次登录。

### 4.2 请求通道

平台接口主要分三类：

1. **直接 HTTP 请求**
   - 通过前端封装或 `window.client.http` 调用。
   - 适用于普通 GET/POST、带 Cookie 的接口。

2. **隐藏 BrowserWindow 执行**
   - 通过 Electron 主进程打开隐藏窗口，加载平台页面或执行 JS。
   - 适用于需要页面上下文、接口签名、msToken、referer、动态 headers 的场景。

3. **插件代理请求**
   - 浏览器插件在真实平台页面内注入 JS。
   - 通过 service worker 代理 fetch/ajax、headers、Cookie 和下载。
   - 适用于平台页面增强按钮、跨页面快捷入口和平台 DOM 交互。

### 4.3 批处理任务模型

商品类批处理功能共用一套任务框架，核心在 `exportFailList-Cu2LCUMb.js`。

典型流程：

1. 选择处理店铺。
2. 导入或筛选商品 ID。
3. 按商品 ID 分页拉取详情。
4. 生成预览结果。
5. 标记每个商品的修改前/修改后状态。
6. 过滤不可处理商品。
7. 并发执行平台修改接口。
8. 记录成功、失败、跳过、异常原因。
9. 导出失败日志或处理结果。

常见任务字段：

- `successNum`：成功数量。
- `errorNum`：失败数量。
- `handleNum`：已处理数量。
- `status`：任务状态。
- `controller`：取消任务控制器。
- `failMsg`：失败原因。
- `shopId/shopName`：所属店铺。
- `productId/goodsId`：商品 ID。

### 4.4 失败日志与本地 DB

批量改价、改标题、运费模板、上下架、删除、达人秀等功能均有失败日志导出设计。页面会将任务状态和临时数据写入本地 SQLite，相关封装通过 `window.client.db` 和 `window.client._db` 暴露。

常见能力：

- 新增任务数据。
- 查询任务数据。
- 删除历史任务。
- 保存商品预览列表。
- 保存失败明细。
- 导出 Excel 文件。

### 4.5 重试与限流

代码里大量处理平台返回的“频繁”“繁忙”“系统错误”“查询异常”等场景。典型策略：

- 分页请求。
- 并发队列控制。
- 遇到频繁/繁忙延迟后重试。
- 单店失败不阻断全部店铺。
- 单商品失败写入失败列表。
- 支持任务取消。

## 5. 功能设计详解

### 5.1 店铺管理

入口：

- 路由：`/dy/shopList`
- 文件：`remote_home\index-R2jGZLVf.js`

页面能力：

- 店铺名称/店铺 ID 查询。
- 店铺状态筛选。
- 分组筛选。
- 功能包或订购状态查看。
- 单店/批量删除。
- 店铺订购操作。
- 更新店铺数据。
- 登录状态展示与登录动作。

主要 UI 字段：

- 店铺名称
- 店铺 ID
- 登录状态
- 分组名
- 功能包状态
- 订购信息

实现逻辑：

1. 页面加载店铺列表，并按搜索条件过滤。
2. 更新店铺数据时逐店刷新登录态、订购态、分组等信息。
3. 删除店铺前校验是否选中。
4. 批量删除按选中店铺执行，完成后刷新列表。
5. 订购动作按选中店铺批量发起，成功后提示设置成功。
6. 登录动作通过本地窗口/session 打开平台登录流程，登录后同步 Cookie 状态。

设计特点：

- 店铺管理是其他功能的基础数据入口。
- 后续功能几乎都依赖这里维护的店铺 ID、名称、登录态和 session。

### 5.5 售中管理

入口：

- 路由：`/dy/managementOfOnSale`
- 文件：`remote_home\index-CDyvcjyo.js`

主要接口：

- `https://fxg.jinritemai.com/api/order/searchlist`
- `https://fxg.jinritemai.com/shopuser/power/getPackageList`
- `https://fxg.jinritemai.com/api/order/receiveinfo`

订单状态：

- 待支付。
- 待发货。
- 已发货。
- 已完成。
- 已关闭。

物流/履约风险：

- 即将揽收、揽收超时、严重超时。
- 即将发运、发运超时、严重超时。
- 中转、配送、疑似遗失、拦截返件。
- 24 小时/48 小时/今日/三天内需发货及揽收。

实现逻辑：

1. 按店铺与筛选条件查询订单列表。
2. 根据订单状态、发货时间、揽收时间、包裹信息计算履约风险。
3. 调用包裹列表接口补充物流节点。
4. 需要时调用收货/地址接口补充订单收件信息。
5. 按风险类型展示订单明细。
6. 支持导出或批量查看。

异常处理：

- 在营销/限时限量购相关页面注入快捷入口。
- 在违规检测相关页面打开小尊宝检测抽屉或外部检测页。
- 在商品编辑页直接操作运费模板表单状态。
- 通过 service worker 代理请求、Cookie、上传、下载、动态 headers。

插件与桌面工具箱的关系：

- 桌面工具箱提供完整批处理页面。
- 插件提供“从平台当前页面跳转/唤起工具”的入口。
- 插件也能补充平台页面上下文，例如选中商品、当前 URL、当前店铺信息。

## 9. 安全与稳定性观察

1. **远程热更新代码执行**
   - 插件会从远程服务下载 JS 并在页面 MAIN world 中执行。
   - 实际逻辑可能随服务端配置变化。
   - 本文档对应下载时的快照，不代表未来线上代码。

2. **跨域和 Web 安全**
   - Electron BrowserWindow 关闭了部分 Web 安全限制。
   - 主进程提供 Cookie、HTTP、文件和窗口控制能力。
   - 需要严格控制远程页面可信边界。

3. **平台接口依赖强**
   - 功能大量依赖抖店/罗盘接口、Cookie、msToken、referer、页面结构。
   - 平台接口变更会导致批处理失败或字段丢失。

4. **滑块/风控不可完全自动化**
   - 售中管理、资金、经营数据等接口可能触发滑块验证。
   - 代码中能识别部分滑块状态，但仍可能需要人工处理。

5. **生产代码压缩**
   - 前端 chunk 无源码映射。
   - 变量名不可读，本文档以接口、路由、文案、导入依赖和调用链还原设计。

## 10. 复现步骤

### 10.1 解包

1. 使用 7-Zip 解开 NSIS 安装包。
2. 提取 `$PLUGINSDIR\app-64.7z`。
3. 解开 `app-64.7z` 得到 Electron 应用。
4. 使用 `@electron/asar` 解开 `resources\app.asar`。

### 10.2 下载远程主站

1. 请求 `https://apptool.zzbtool.com`。
2. 下载入口 HTML 引用的 JS/CSS。
3. 从入口 JS 的 Vite 动态依赖列表解析 chunks。
4. 下载全部动态 chunks。
5. 按中文功能名、路由、接口关键字建立索引。

### 10.3 下载远程插件

1. 请求 `https://plug1.zzbtool.com/zzbPlug/v3config`，补齐插件请求头。
2. 读取 `cssUrls`、`jsUrls`、`popUrl`。
3. 下载 `v3_all.js`、`v3_ext.css`、Popup HTML。
4. 按按钮文案、平台 URL、路由关键字检索插件能力。

## 11. 结论

小尊宝工具箱 V2.1.6 的目标功能不是一个纯本地 EXE 内置工具，而是由三部分协同实现：

1. **Electron 本地壳**：提供 Cookie、HTTP、窗口、下载、文件、DB、自动更新等能力。
2. **远程 Vue Web 应用**：承载店铺管理、经营数据、资金数据、营销、商品批处理等完整业务页面。
3. **远程热更新插件代码**：在平台页面注入入口和自动化逻辑，辅助跳转和页面内操作。

本次要求的 16 个功能中，店铺管理、经营数据、资金数据、违规管理、售中管理、限时限量购、新人礼金、通用优惠券、商机提报、清理滞销均有各自独立页面 chunk；批量上下架、批量删除、达人秀修改、批量改标题、批量改价、运费模板则明显共享同一个商品批处理底座，通过不同配置和计算器派生出具体业务能力。
